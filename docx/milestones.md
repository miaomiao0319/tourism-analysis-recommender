## 1. 维护边界与更新方法

**本文件是日常进度维护例外。** agent 可以直接更新自己的任务状态、实际日期、产物和验证证据、阻塞与下一步；也可在既定职责和范围内补充必要子任务、细化实现依赖。普通进度更新不逐次请求人工批准，不新建另一份共享 TODO、看板或进度日志代替本文件。

这一例外不授权改变需求、必用技术、角色职责、字段/API/环境约定、验收标准或其他受保护文档。需要改变这些约定时，先展示具体变更并获得人工明确批准，再同步相关规范与进度；不能通过删除必做任务、降低完成依据、移动到“可选”或把 blocked 改成 done 来取消要求。

更新前重读最新文件并核对工作区，只改本任务相关条目和必要关联状态，不覆盖其他角色的记录。共同任务由实际完成验证的 agent 更新，注明各角色的实际贡献；没有对方产物或验证证据，不能替其宣称完成。发现旧状态错误时纠正并保留简短依据，不机械维护一份明知失真的进度表。

日期只记录真实发生的工作、验证或批准，不补造历史日期。项目截止日及各阶段计划日期均未确定，不填写推测的周次或交付日期。**2026-10 是数据时间截止月，不是项目截止日期。** 没有最低数据量指标，不用人为数量门槛或重复记录决定完成。

## 2. 状态与完成的含义

| 状态 | 使用条件 |
| --- | --- |
| `todo` | 尚未开始；前置条件可能未满足，不能据此认为已获准立即执行。 |
| `in_progress` | 已在授权范围实际开展，记录本次工作入口与尚未完成部分。 |
| `blocked` | 任务确实因具体缺失或冲突不能继续；写明缺什么、涉及哪个任务/角色、解除条件以及仍可做什么。 |
| `in_review` | 产物已形成，等待本任务实际需要的人工验收、审查或接入验证；未做的检查继续明确列出。 |
| `done` | 本行承诺的产物与必要检查均已完成，所要求的验收或接入已有证据；不能仅凭文件存在或 agent 自称完成。 |

任务状态与 Git 状态分开：本地成稿、已提交、已推送、Draft PR、Ready、已合并分别据实记录，不把提交、合并或 health 成功直接当作功能通过。代码任务的自身实现可以完成，但相关接入任务仍为 todo；阶段通过还需满足该阶段整体完成依据。

阶段是否通过以任务和证据判断，不按已写文件数、提交数、数据行数或自报百分比推算。普通实施阶段不新增逐阶段人工签字要求，agent 可在条件确实满足后更新阶段状态；规范验收、规范修改及合并 main 仍遵循已有人工授权边界。

5. 已有本人任务为 in_progress/in_review 时优先完成或跟进；依赖阻塞则记录后继续其他就绪工作，不接管其他角色的任务来掩盖缺口。
